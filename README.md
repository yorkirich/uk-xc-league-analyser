# UK XC League Analyser

An interactive chart of how the UK XC League 2026 standings developed through the season. You can pick pilots (top N, individual pilots, a pilot and their neighbours, or a club) and see their rank or score day by day. You can also see the six flights behind each pilot's score, with links to each flight on xcleague.com.

It's a static site: one HTML page plus one JSON data file. There's no server code, no database and no build tooling beyond a small Node script.

## Files

| File | What it is |
|---|---|
| `index.html` | The whole web app: HTML, CSS and JavaScript in one file, with no external libraries. |
| `league-2026.json` | Compact season data that the page loads (pilots, flights, lookups). Generated by `build.js`. |
| `build.js` | Node script that converts the XC League API export into `league-2026.json`. |
| `raw/league.json` | The original export from the XC League API (kept so the data can be rebuilt without fetching again). |
| `README.md` | This file. |

## Data source

The data comes from the XC League's own JSON export:

```
https://xcleague.com/xc/api.php?output=json&service=flights&year=2026
```

It returns every valid flight in the league year, with pilot ID, name, club, flight date, flight type, site, glider, score and a link to the flight page.

**Load on xcleague.com:** the 2026 league is closed, so the data is final. It was downloaded once and is served from this site. Visitors never contact xcleague.com, except when they click through to a flight.

**Permission:** the UK XC League has given permission to publish this data. Their site's robots.txt (`User-agent: * / Disallow: /`) asks automated tools not to crawl it, so any *scheduled* automatic fetch (for a live season) should still be agreed with them first.

**Credit:** the page shows a source line crediting the UK XC League and the export date.

## How the standings are calculated

- A pilot's league score on any date is the **sum of their best 6 flights** flown on or before that date (confirmed against the league rules).
- Rank on a date is the order of those scores. Tied pilots share a rank, and pilots with no flights yet are unranked.
- The league year runs **1 November to 31 October** (2026 season: 1 Nov 2025 to 31 Oct 2026).
- The glider shown for a pilot is the one flown on their **highest-scoring flight**, which matches the official table.
- Two pilots with the same name are shown with their club, e.g. "Richard Carter (Cayley)".

**Verified:** the final standings match the official 2026 National League table for all of the top 30 pilots on rank, name, club, total and glider. They also match the headline figures: 2,393 flights, 169,400.3 points and 277 pilots.

**Caveat:** the history is rebuilt from the *final, moderated* flight list. Flights submitted late, or later removed, mean the chart can differ slightly from what the live table showed on a particular day.

## Using the page

**Show** (which pilots):
- **Top N**: the top N at the "Ranked at" date.
- **Chosen pilots**: type a name to add it (suggestions are listed as "Surname, First name"; either order works), and × to remove it.
- **Around a pilot**: a pilot plus N places either side at the "Ranked at" date.
- **Club**: the top N within a club.

**Ranked at**: the date used to choose pilots for Top N, Around and Club, and for the Flights view and the table. Drag the slider, or click the line chart.

**Chart**:
- **Line**: rank (1 at the top) or score over time. **Period** sets the x-axis range. It fits the first to last flight of the pilots shown (plus 2 days either side) and refits when the selection changes. A Period you set yourself stays until then, and **Reset** fits it again. Hover for values on any date. A **legend below the chart** lists the pilots in rank order. Hover a line, legend entry or table row to pick out that pilot: their line thickens, the others fade, and their name and rank appear at the end of the line. **Click** to keep them picked out; click again or press Esc to release. Clicking an empty part of the chart moves the ranking date.
- **Flights**: one pilot at a time. Choose any pilot in the **Pilot** box (every pilot, listed as "Surname, First name" in surname order), or click a row in the table. The choice stays when the Show settings change, on the same time axis and **Period** as the line chart.
  - There's a bar on each day the pilot flew, stacking the flights that counted towards their score after that day (best 6 so far, oldest at the bottom). The bar's height is their league score on that day, and a **line** shows that total day by day.
  - **Colours** mark the 6 flights that end up as the pilot's final best (Flight 1–6, as in the league table). **Grey** flights counted for a while and were later replaced by better ones. The flight added on that day is the top segment. A **hollow circle** above a bar is a flight that didn't count even on the day it was flown.
  - Above the chart, a summary in the style of the league table shows the pilot's club, glider and rank, their final total, and their best 6 flights. Each flight shows its score with an icon for the flight type, drawn by us and following the league's colour conventions. The symbol shows the flight's shape: right-angle arrow = turnpoint, straight arrow = flight to goal, double-headed arrow = out & return, filled triangle = FAI triangle, outline triangle = flat triangle, double chevron = open distance, right-angle arrow over a wave = coastal turnpoint. A **yellow symbol** means declared, and a **green tile** means tow-launched (otherwise a white symbol on a blue tile). The key lists only the icons shown. Each flight's coloured edge matches its bar colour; hover for its type, date and site, and click to open it. Hover a segment for its date, site, flight type, glider and status; click it to open the flight on xcleague.com.
  - The **Period** fits the pilot's own flights (first to last flight, plus 2 days either side, at least 3 weeks) and refits when you change pilot. You can still change it, and **Reset** fits it again.
  - **Time scale**: all bars are the same width.
    - **Compact** (default): each flying day gets an equal slot, and a run of *g* days without flights takes 0.5×√*g* slots. Long quiet spells shrink a lot and short gaps barely change, so months are no longer equal widths. Faint vertical lines mark the start of each month.
    - **Calendar**: true dates. Bars are as wide as the two closest flying days allow, so they're thin for a pilot who flew on consecutive days.
  - Showing several pilots at once (e.g. small multiples) is still to be designed.

**Colours:** each pilot keeps a colour while they stay on the chart. There are 8 colours. Pilots 9–16 get dashed lines and 17–24 dotted lines, so lines stay distinguishable. Light and dark mode follow the device setting.

## Running locally

The page loads `league-2026.json` with `fetch()`, so it must be served over HTTP. Opening `index.html` directly from disk won't work. From this folder, run either:

```
npx serve .
```
or
```
python -m http.server 8000
```
then open http://localhost:8000 (or the address `serve` prints).

## Rebuilding the data

Requires Node 18+.

1. Download the export (in a browser, or with curl) and save it as `raw/league.json`:
   `https://xcleague.com/xc/api.php?output=json&service=flights&year=2026`
2. Run:
   ```
   node build.js raw/league.json league-2026.json
   ```
   It prints a summary such as `277 pilots, 2393 flights, 2025-11-06 to 2026-10-30`.

`build.js` keeps only flights with `valid = 1`. It stores flight types, gliders and sites once in lookup lists to keep the file small (about 200 KB). It also writes the season dates, the best-6 rule and the flight link template into the file.

### `league-2026.json` format

```json
{
  "season": "2026", "bestN": 6, "start": "2025-11-01", "end": "2026-10-31",
  "source": "UK XC League (xcleague.com), exported …",
  "flightUrl": "https://xcleague.com/xc/flights/{f}.html",
  "types":   ["Turnpoint Flight", "…"],
  "gliders": ["Ozone Zeno 2", "…"],
  "sites":   ["Talybont", "…"],
  "pilots":  [{ "id": "1338", "name": "Ben Abell", "first": "Ben", "last": "Abell", "club": "Derbyshire", "wing": "BGD Lynx 2" }],
  "flights": [{ "p": "1338", "d": "2026-05-24", "s": 10.7, "f": 20261461, "t": 0, "g": 3, "x": 12 }]
}
```
In each flight, `p` is the pilot ID, `d` the date, `s` the score and `f` the flight number (used in `flightUrl`). `t`, `g` and `x` are indexes into `types`, `gliders` and `sites`.

## Deploying (Cloudflare Pages)

1. Put this folder in a GitHub repository (include `league-2026.json`; `raw/` is optional).
2. In Cloudflare: **Workers & Pages → Create → Pages → Connect to Git** and choose the repo.
3. Build settings: no framework, **no build command**, output directory `/` (the repo root).
4. Each push to the main branch redeploys.

No Worker, KV or R2 is needed, because all the data is static.

- **More filters:** glider make or class, flight type, "biggest movers between two dates".
