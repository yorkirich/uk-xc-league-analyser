# UK XC League Analyser

An interactive chart of how the UK XC League standings developed through each season, from 2005 to 2026. You can pick pilots (top N, individual pilots, a pilot and their neighbours, or a club) and see their rank or score day by day. You can also see the six flights behind each pilot's score, with links to each flight on xcleague.com.

**Live site:** https://uk-xc-league-analyser.pages.dev

It's a static site: one HTML page plus one JSON data file per season. There's no server code, no database and no build tooling beyond a small Node script.

## Files

| File | What it is |
|---|---|
| `index.html` | The whole web app: HTML, CSS and JavaScript in one file, with no external libraries. |
| `data/league-YYYY.json` | Compact data for one season that the page loads (pilots, flights, lookups). Generated by `build.js`. |
| `data/seasons.json` | The list of seasons for the Season menu, newest first. Generated by `build.js`. |
| `build.js` | Node script that converts the XC League API exports into the `data/` files. |
| `raw/league-YYYY.json` | The original export for each season from the XC League API, kept so the data can be rebuilt without fetching again. |
| `README.md` | This file. |

## Data source

The data comes from the XC League's own JSON export:

```
https://xcleague.com/xc/api.php?output=json&service=flights&year=YYYY
```

There's one export per season, from 2005 to 2026. Each returns every valid flight in that league year, with pilot ID, name, club, flight date, flight type, site, glider, score and a link to the flight page.

**Load on xcleague.com:** all of these seasons are closed, so the data is final. Each season was downloaded once, a few seconds apart (2026 on 23 Nov 2026 at 17:01 UTC, 2005–2025 the same evening), and is served from this site. Visitors never contact xcleague.com, except when they click through to a flight.

**Permission:** the UK XC League has given permission to publish this data. Their site's robots.txt (`User-agent: * / Disallow: /`) asks automated tools not to crawl it, so any *scheduled* automatic fetch (for a live season) should still be agreed with them first.

**Credit:** the page shows a source line crediting the UK XC League and the export date.

## How the standings are calculated

- A pilot's league score on any date is the **sum of their best 6 flights** flown on or before that date (confirmed against the league rules).
- Rank on a date is the order of those scores. Tied pilots share a rank, and pilots with no flights yet are unranked.
- The league year runs **1 November to 31 October** (2026 season: 1 Nov 2025 to 31 Oct 2026). Every flight in every season from 2005 to 2026 falls inside these dates.
- The best-6 rule applies to every season from 2005 to 2026 (confirmed).
- A **club's** score on any date is the **sum of its best 4 pilots' league scores** on that date, as in the league's Club Flights table. Clubs are ranked the same way as pilots. A pilot belongs to the club recorded on their flights for that season.
- The glider shown for a pilot is the one flown on their **highest-scoring flight**, which matches the official table.
- Two pilots with the same name are shown with their club, e.g. "Richard Carter (Cayley)".

**Verified:** the final standings match the official 2026 National League table for all of the top 30 pilots on rank, name, club, total and glider. They also match the headline figures: 2,393 flights, 169,400.3 points and 277 pilots. The 2026 club standings match the official Club Flights table for the top 4 clubs (Dales 5,949.2, Cumbria 5,879.5, Derbyshire 4,828.1, Grupa 303 4,747.1), including each club's four counting pilots and its number of pilots.

**Caveat:** the history is rebuilt from the *final, moderated* flight list. Flights submitted late, or later removed, mean the chart can differ slightly from what the live table showed on a particular day.

## Using the page

**Season**: picks the league year, 2005 to 2026, with the newest first. Changing season keeps your other settings. Pilots you'd chosen stay chosen if they also flew in the new season, and the ranking date moves to the end of that season.

**Standings**: **Pilots** or **Clubs**. Every view below works for both. In Clubs, the lines, legend and table show clubs, and the Breakdown view shows one club. Pilots and clubs each remember their own chosen names, Around name, Flights choice and picked-out line, so switching back and forth doesn't lose them.

**Show** (which pilots or clubs):
- **Top N**: the top N at the "Ranked at" date.
- **Chosen pilots / clubs**: type a name to add it (pilot suggestions are listed as "Surname, First name"; either order works), and × to remove it.
- **Around a pilot / club**: one pilot or club plus N places either side at the "Ranked at" date.
- **Club** (Pilots only): the top N pilots within a club.

**Club table** (Clubs, Compare view): each club's best 4 pilots and their scores at the "Ranked at" date, then the club's rank, score, and number of pilots with a score so far.

**Ranked at**: the date used to choose pilots for Top N, Around and Club, and for the Breakdown view and the table. Drag the slider, or click the line chart.

**Chart**:
- **Compare** (line chart): score (the default) or rank (1 at the top) over time. **Period** sets the x-axis range. It fits the first to last flight of the pilots shown (plus 2 days either side) and refits when the selection changes. A Period you set yourself stays until then, and **Reset** fits it again. Hover for values on any date. A **legend below the chart** lists the pilots in rank order. Hover a line, legend entry or table row to pick out that pilot: their line thickens, the others fade, and their name and rank appear at the end of the line. **Click** a line or table row to keep them picked out; click again or press Esc to release. **Click a name in the legend** to open that pilot's (or club's) Breakdown view. Clicking an empty part of the chart moves the ranking date.
- **Breakdown** (stacked bars): one pilot at a time. Choose any pilot in the **Pilot** box (every pilot, listed as "Surname, First name" in surname order). The pilot table is hidden in this view, because the summary above the chart already covers the pilot. The choice stays when the Show settings change, on the same time axis and **Period** as the line chart.
  - There's a bar on each day the pilot flew, stacking the flights that counted towards their score after that day (best 6 so far, oldest at the bottom). The bar's height is their league score on that day, and a **line** shows that total day by day.
  - **Colours** mark the 6 flights that end up as the pilot's final best (Flight 1–6, as in the league table). **Grey** flights counted for a while and were later replaced by better ones. The flight added on that day is the top segment. A **hollow circle** above a bar is a flight that didn't count even on the day it was flown.
  - Above the chart, a summary in the style of the league table shows the pilot's club, glider and rank, their final total, and their best 6 flights. Each flight shows its score with an icon for the flight type, drawn by us and following the league's colour conventions. The symbol shows the flight's shape: right-angle arrow = turnpoint, straight arrow = flight to goal, bold double-headed arrow = out & return, filled triangle = FAI triangle, right-angled triangle = flat triangle, double chevron = open distance, right-angle arrow over a wave = coastal turnpoint. A **yellow symbol** means declared, and a **green tile** means tow-launched (otherwise a white symbol on a blue tile). The key has one entry for each icon shown, such as "declared FAI triangle" or "tow-launch flight to goal". Each flight's coloured edge matches its bar colour; hover for its type, date and site, and click to open it. Hover a segment for its date, site, flight type, glider and status; click it to open the flight on xcleague.com.
  - **Show** (in Breakdown) chooses which flights get a bar:
    - **All** (default): every flying day, with hollow circles for flights that never counted.
    - **Scoring**: only days with a flight that counted at the time. Flights that never counted are left out.
    - **Best**: only the days the final best 6 were flown, and each bar stacks just those flights flown so far. The total line still shows the full league total, so it can sit above the bars while flights that were later replaced were counting.

    Changing this refits the Period, the bar width and the Compact time compression to the flights shown.
  - **For a club** (Standings: Clubs), choose the club in the **Club** box. There's a bar on each day any of its pilots flew. The bar stacks the pilots counting for the club after that day (up to 4), and each segment is that pilot's league score. The line is the club score.
    - **Colours** are the club's final 4 pilots, with pilot 1 at the bottom. **Grey** pilots counted for a while and were later overtaken by clubmates.
    - A **hollow circle** marks a pilot who flew that day without adding to the club score.
    - **Show:** All shows every flying day. Scoring shows only days the club score went up. Best shows only days one of the final 4 pilots' scores went up, stacking just those 4.
    - Above the chart, the summary shows the club's rank, total and final 4 pilots. Click a pilot there, or any segment, to open that pilot's Breakdown view.
  - The **Period** fits the pilot's own flights (first to last flight, plus 2 days either side, at least 3 weeks) and refits when you change pilot. You can still change it, and **Reset** fits it again.
  - **Time scale**: all bars are the same width.
    - **Compact** (default): each flying day gets an equal slot, and a run of *g* days without flights takes 0.5×√*g* slots. Long quiet spells shrink a lot and short gaps barely change, so months are no longer equal widths. Faint vertical lines mark the start of each month.
    - **Calendar**: true dates. Bars are as wide as the two closest flying days allow, so they're thin for a pilot who flew on consecutive days.
  - Showing several pilots at once (e.g. small multiples) is still to be designed.

**Colours:** each pilot keeps a colour while they stay on the chart. There are 8 colours. Pilots 9–16 get dashed lines and 17–24 dotted lines, so lines stay distinguishable. Light and dark mode follow the device setting.

## Running locally

The page loads its `data/` files with `fetch()`, so it must be served over HTTP. Opening `index.html` directly from disk won't work. From this folder, run either:

```
npx serve .
```
or
```
python -m http.server 8000
```
then open http://localhost:8000 (or the address `serve` prints).

## Rebuilding the data

Requires Node 18+.

1. For each season you need, download the export (in a browser, or with curl) and save it as `raw/league-YYYY.json`:
   `https://xcleague.com/xc/api.php?output=json&service=flights&year=YYYY`
2. Run:
   ```
   node build.js
   ```
   This builds every `raw/league-YYYY.json` into `data/league-YYYY.json` and writes `data/seasons.json`. It prints one line per season, such as `2026: 277 pilots, 2393 flights, 169400.3 points, 2025-11-06 to 2026-10-30`. To build just one season, run `node build.js raw/league-2026.json data/league-2026.json`. That doesn't update `seasons.json`.

To add a new season (e.g. 2027), save its export as `raw/league-2027.json` and run `node build.js`. It then appears in the Season menu.

`build.js` keeps only flights with `valid = 1`. It stores flight types, gliders and sites once in lookup lists to keep the file small (about 200 KB). It also writes the season dates, the best-6 rule and the flight link template into the file.

### `data/league-YYYY.json` format

```json
{
  "season": "2026", "bestN": 6, "start": "2025-11-01", "end": "2026-10-31",
  "source": "UK XC League (xcleague.com), exported …",
  "flightUrl": "https://xcleague.com/xc/flights/{f}.html",
  "types":   ["Turnpoint Flight", "…"],
  "gliders": ["Ozone Zeno 2", "…"],
  "sites":   ["Talybont", "…"],
  "pilots":  [{ "id": "1338", "name": "Ben Abell", "first": "Ben", "last": "Abell", "club": "Derbyshire", "wing": "BGD Lynx 2" }],
  "flights": [{ "p": "1338", "d": "2026-05-24", "s": 10.7, "f": 20261461, "t": 0, "g": 3, "x": 12 }]
}
```
In each flight, `p` is the pilot ID, `d` the date, `s` the score and `f` the flight number (used in `flightUrl`). `t`, `g` and `x` are indexes into `types`, `gliders` and `sites`.

## Deploying (Cloudflare Pages)

The repo is https://github.com/yorkirich/uk-xc-league-analyser. It's connected to the Cloudflare Pages project `uk-xc-league-analyser`, which has no framework, **no build command** and serves the repo root.

- Each push to `main` redeploys https://uk-xc-league-analyser.pages.dev.
- Pushes to other branches get their own preview URLs.

No Worker, KV or R2 is needed, because all the data is static.

## Possible next steps

- **Check earlier seasons:** compare a few older final tables (pilots and clubs) with the official ones.
- **Live season (2027):** a daily GitHub Action (download → `build.js` → commit) and Pages redeploys automatically. That's one request a day to xcleague.com. Agree this with the league first (see robots.txt above).
  - **Deleted or changed flights:** during a live season, flights can be removed or invalidated after they first appear (moderation, late corrections), and their scores can change. Each day's export only shows the current list, so a rebuilt history silently rewrites the past. Before building this, decide how to handle it. For example, keep each day's export (or a diff), mark flights that later disappeared, and decide whether the chart should show the standings as they were on the day or as corrected.
- **Shareable links:** store the selection in the URL query string.
- **More filters:** glider make or class, flight type, "biggest movers between two dates".
